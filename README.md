# bangumi-staff-analyzer

Bangumi 制作人员（staff）分析与收集工具。纯前端 Web 应用，**双击 `index.html` 即可使用**，无需安装、无需 Token、无需后端。

## 功能

- **公司 staff 频率统计**：搜索一家制作公司（如「京都动画」），统计其作品中哪些制作人员出现的次数最多、各自担任过哪些职务。
- **个人共事统计**：搜索一位个人（如某位制片人/监督），统计与 TA 共事过的人及共事作品数——可用于梳理「某制片人的班底/人脉」。
- **作品重叠度对比**：选两部作品，查看同时出现在两部作品中的 staff，以及他们在两部作品里各自担任的职务（如 A 里是监督、B 里是演出）。
- **我的分类收集**：给感兴趣的 staff 打标签、写备注、建自定义分组（如「山田尚子班底」），数据保存在本地浏览器（IndexedDB），支持导出 JSON / CSV 备份。

## 数据来源与隐私

- 数据来自 Bangumi 官方公开 API（https://api.bgm.tv），无需登录、无需 Access Token。
- 所有抓取到的数据与你的标记/分组都只保存在**本地浏览器**中，不上传任何服务器。
- 清除浏览器站点数据会清空本工具的全部本地数据，建议定期导出备份。

## 安装与使用

1. 方式一（最简单）：双击打开 `index.html`。
2. 方式二（推荐，更稳定）：在项目目录启动一个本地静态服务器，然后访问 `http://localhost:8000`：

   ```bash
   python3 -m http.server 8000
   ```

3. 首页搜索「京都动画」「山田尚子」等名称 → 点击进入分析页。
4. 「作品重叠度对比」页搜索或粘贴条目链接（如 `https://bgm.tv/subject/876`）即可对比。

> 提示：双击打开（file://）时少数浏览器对 IndexedDB 有额外限制；若遇到"无法保存数据"，请改用方式二。

## 关于请求频率

批量统计（如公司几百部作品）会向 Bangumi API 逐个请求，请合理设置：

- **并发数**：建议 3-10，默认 5（设置里可调，1-20）。
- **请求间隔**：建议 150-500ms，默认 200ms。
- 遇到大量 `429` 报错或「请求多次失败」时，请把并发降到 3、间隔加到 400ms 以上再重试，并勾选「强制刷新缓存」前先清理失败项。
- 已抓取的数据会缓存在本地，重复统计同一批作品会直接命中缓存，不会重复请求。

## 常见问题

- **搜索无结果**：换关键词，或去掉职业筛选。
- **统计结果缺失个别作品**：Bangumi 部分条目 staff 数据不全，属正常现象；统计页会提示失败数量。
- **某个 staff 点击「收集」没反应**：确认浏览器支持 IndexedDB，且未以隐私模式阻止本地存储。
- **页面渲染异常**：按 F12 打开控制台，把报错信息发给我排查。
