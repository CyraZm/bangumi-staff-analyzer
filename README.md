# bangumi-staff-analyzer · v1.9.1

Bangumi 制作人员（staff）对比与制片人班底分析工具。高对比度分析工作台，附带无终端窗口的 macOS 启动应用。数据分析在浏览器中完成，无需登录或 Token；本地服务只负责提供页面和控制应用退出。

## 功能

- **公司 staff 频率统计**：搜索一家制作公司（如「京都动画」），统计其作品中哪些制作人员出现次数最多、各自担任过哪些职务；作品可按参与身份（如动画制作）筛选，结果可按职务（监督/原画/演出等）筛选，**每个职务单独计数**（如某人导演×10、演出×20，筛选某职务时显示对应次数）。
- **个人共事统计**：搜索一位个人（如某位制片人/监督），统计与 TA 共事过的人及共事作品数。共同参与仅作为合作线索，不自动推断固定班底。
- **作品对比（支持多部）**：选择 2–8 部作品，动画制作公司与动画制片人列在每部作品下方；中间只对导演、脚本、分镜、作画、美术、摄影、音响、音乐，以及制作进行、制作管理、设定制作等现场岗位的**个人与创作组合**计算交集。企划、製作、出品与一般制片等署名，以及公司、原作和未识别职务在底部单独列出。独立署名按 Bangumi ID 判断重合并同步高亮，优先采用条目信息框的署名顺序，无法核对时明确标注。两部作品只显示一张交集表；三部以上可切换「至少两部共同 / 全部共同」，并查看每部作品独有的制作人员。
- **公司对比**：选两家及以上制作公司，自动聚合各公司「动画制作」作品的全部 staff，找出同时出现在多家公司作品中的 staff（带出现次数与职务）——可用来观察 staff 在不同公司间的流动。
- **仅当次临时保留**：首页搜索、人物/公司统计、作品/公司对比和班底报告在应用内切页后保留；刷新、关闭页面或退出应用后清空，不恢复旧结果。作品/公司对比两种模式独立保留，需要重新开始时点「清空本次对比」。
- **制片人班底分析**：默认使用其全部明确动画/制作制片署名的作品与全部合作 staff，制作进行等现场岗位共事单独作辅助，企划/资方不作班底依据。结合主要岗位的合作集中度及延续、总数量、系列项目覆盖、近作权重与外部合作广度，区分核心候选、稳定合作、高频外部合作、系列内合作、近作合作减少、待观察；有逐项证据、当次临时保留、取消和导出。无手动年份/范围筛选。具体定义见 [方法说明](TEAM_METHOD.md)。
- **岗位排序**：班底、作品/公司对比及人员统计默认按导演→演出→分镜→其他岗位排列，同岗位再参考合作情况；统计与班底页面可切换指标排序。

## 数据来源与隐私

- 数据来自 Bangumi 官方公开 API（https://api.bgm.tv），无需登录、无需 Access Token。
- 搜索时的「个人/公司」标签来自 Bangumi 人物条目的类型字段；「制片人/画师/声优」等来自其职业（career）字段的官方分类，由 Bangumi 用户维护，非本工具自行判断。
- 查询响应与分析结果只保留在**当前页面内存**中，不自动写入本地数据库、localStorage 或 sessionStorage；应用不上传分析记录。
- 仅并发数、请求间隔等偏好设置保存在本机。需要留存的名单由用户主动导出；升级时自动删除旧版持久保存的对比/班底结果和 API 缓存。

## 如何分析制片人班底

1. 点击侧栏 **制片人班底**，搜索姓名或粘贴 Bangumi 人物链接 / ID。内置梅原翔太（27888）、福士裕一郎（30844）、丸山正雄（914）三个入口。
2. 自动读取其全部明确动画/制作制片身份的作品，点 **分析全部制片作品**。逐片核实人员表；其他现场岗位的共事另列为辅助，不混入制片合作次数。
3. 等待分阶段核查，可随时取消；所有跨项目重复合作者都核对外部履历，不抽样。首次作品多时耗时更久，本次打开期间可复用查询缓存。
4. 看总合作、同岗位合作/全部履历、延续证据和近作加权覆盖，点 **查看依据** 核对实际作品、本人在该片的制片身份和候选 staff 的职务。总体减少但主要岗位或待播合作仍在延续时，不直接降级。
5. 默认岗位优先，历史下降关系置后；可按加权覆盖、项目组数或总合作数查看。结果仅在本次打开期间保留，切页不丢失；刷新或关闭后清空，支持主动 JSON / CSV 导出。

不使用年份跨度或合作持续月份判断班底。日期仅辅助排列公开作品的相对新旧，不能视为实际开工时间。总集篇保留记录但不重复增加近作权重。

普通「制片人」「联合制片人」「执行制片人」等作品单独列出，完全不参与班底样本与合作计数，不依据年代自动等同为动画制片人。结果也不能证明雇佣、私交或 web 身份。完整规则见 [TEAM_METHOD.md](TEAM_METHOD.md)。旧人物收藏页面及按钮已移除，历史数据库记录保留但不参与新判断。

## 作品对比的统计范围与顺序

- 依据本作品的 `relation` 职务和 `type` 实体类型分类，不根据人物整体职业猜测参与方式。职位清单参照 [Bangumi 官方定义](https://github.com/bangumi/common/blob/master/subject_staffs.yml)，字段依据 [官方 API](https://github.com/bangumi/api/blob/master/open-api/v0.yaml)。
- 制作现场的进度与交付岗位纳入人员交集：制作进行、制作进行协力、制作管理及助理、设定制作及助理、制作统括、制作事务、个人制作协力、CG/美术制作进行、音响制作担当、剧本协调、制作制片人（官方 Production Producer / 制作プロデューサー）。制作进行参照 [CloverWorks 官方职种介绍](https://cloverworks.co.jp/recruit/)与 [MAPPA 制作部说明](https://www.mappa.co.jp/recruit/)；设定制作参照 [BONES 官方制作日志](https://www.bones.co.jp/skullman_yota/)。相应职位名称仍以 Bangumi 官方定义为准。
- 「制作统括／制作协力」与「製作统括／製作协力」分别处理；后者保留在底部。「制作助理」在官方职位定义中是 Associate Producer / 製作補佐，不等同于制作管理助理，仍独立展示。动画制作公司与动画制片人继续在上方独立列出。
- 一人兼任导演与企划时，人员交集只含导演职务，企划署名仍在底部。只有在另一作品也有符合范围的制作职务，才算两部共同制作人员。动画制片人不计入人员交集。
- 个人（type=1）与创作组合（type=3）只要担任纳入范围的制作职务，就参与交集；例如劇団イヌカレー的演出、分镜。组合明确标记，保留原 ID 与类型，不拆分/推测成员；计数统一为制作署名，同一组合在一部作品担任多个职务只计一项。公司（type=2）继续独立展示，未识别职务保留在底部。数据中的类型可能被站内用户误标，本工具不凭名称改写身份。
- 所有独立署名不按姓名、出现次数或重合状态排序，不截断关联名单。优先按条目 `infobox` 中对应职务的署名原文排序，可展开原文；所有关联姓名都能唯一对应时才采用该顺序。缺失或不明确时沿用关联接口顺序，逐项标注「顺序未核实」，避免伪造企划出资排序。官方关联人员接口没有提供署名顺序字段（实现也未按此排序）；API 没有投资金额或比例，因此不推断出资份额。信息框可能包含尚未关联人物条目的名字，关联列表以人物 API 为准，原文完整保留供核对。
- 同一实体在同一作品有多项独立署名，只算出现于一部；在至少两部作品的独立署名中出现，才在各处标记「重合」。
- 原有公司频率分析、个人共事统计与公司对比的职务范围保持原规则；本次分类适用于**作品对比**。

## 如何打开 / 关闭（重要）

推荐双击项目目录中的 **`Staff Analyzer.app`**：

1. **打开**：双击应用，自动启动本地服务并打开默认浏览器，全程不弹终端。可以把应用拖到 Dock，或复制到「应用程序」文件夹。
2. **关闭**：点击页面侧边栏的 **「关闭应用」**。服务、请求队列、重试和打开的其他本工具标签页会停止工作；应用的 Dock 图标也会退出。浏览器可能保留「已结束本次探索」页面，直接关闭标签页即可。
3. **从 Dock 退出**：右键应用图标 →「退出」，或应用激活时按 Command + Q，也会停止本地服务。页面随后显示服务已断开。
4. **重复打开**：复用已经运行的本工具服务，不重复占用端口。若 8000 被其他程序或旧版终端服务占用，会提示先关闭原服务，不会结束其他程序。

仅关闭浏览器标签页不会退出应用；请用页面按钮或 Dock 菜单退出。

**已有数据**：继续使用原来的 `http://localhost:8000`，数据库名称和格式均未更改。请使用与之前相同的浏览器和用户配置。此前直接双击 `index.html` 的本地数据属于另一来源；新版不恢复历史分析结果。

启动地址会附带版本和本次打开的标识，页面的样式、脚本、图标也带版本号，避免 Edge 等浏览器沿用旧界面缓存。这些参数不改变偏好设置的存储位置；旧分析结果和 API 缓存会自动清理，无需手动清除站点数据。若旧标签页仍显示旧界面，关闭旧标签页后重新双击最新版应用。

应用需要本机已有 Python 3（当前电脑已具备），不额外安装第三方 Python 包。若刚从代码仓库下载，还没有 `.app`，可在装有 Apple Command Line Tools 的 Mac 上生成一次：

```bash
bash scripts/build-macos.sh
```

修改源代码后需重新运行上述打包命令，应用资源才会更新。重绘图标运行 `bash scripts/build-icon.sh`；图标为本项目自制矢量图形。构建输出 `Staff Analyzer.app` 不纳入 Git。

开发时可运行 `python3 server.py`，然后打开 `http://localhost:8000`；页面关闭按钮同样有效。直接打开 `index.html` 或使用普通静态服务器时显示「浏览器模式」，按钮只能停止当前页面任务，不能管理外部服务。`start.command` 仅保留为旧入口兼容，双击它仍会由 macOS 打开终端，因此日常请使用 `.app`。

本地服务仅监听 `127.0.0.1`；关闭接口校验来源与每次启动生成的令牌，不按端口查杀进程。启动器异常退出后，子服务会自行停止。

## 当次运行的缓存

首页搜索、人物/公司统计、作品/公司对比和制片人班底报告仅保存在当前页面内存。切去其他功能再回来时，输入、结果、筛选、展开项与阅读位置继续保留；已开始的统计可在离开后完成。作品和公司对比各自保留状态，人物/公司统计按所查看的对象保留。

刷新页面、关闭标签页、退出应用或重新打开时，不恢复上次结果。新标签页也是独立的一次使用。查询响应同样仅作当次内存缓存，不写入磁盘；升级时删除旧版本保存的两个工作区和 API 缓存，仅保留偏好设置。

「清空本次对比」只重置当前对比模式；「清空 API 缓存」只清当前查询缓存，保留正在查看的结果；「清空全部本地数据」同时清空当前各页面结果、临时缓存及全部偏好/历史本地记录。需要长期保留班底名单时可主动导出 JSON / CSV。

## 关于请求频率

批量统计（如公司几百部作品）会向 Bangumi API 逐个请求，请合理设置：

- **并发数**：建议 3-10，默认 5（设置里可调，1-20）。
- **请求间隔**：建议 150-500ms，默认 200ms。
- 遇到大量 `429` 报错或「请求多次失败」时，请把并发降到 3、间隔加到 400ms 以上再重试。
- 本次已查询的数据会复用内存缓存；刷新或重新打开后会重新请求。

## 常见问题

- **搜索无结果**：换关键词再试。
- **公司统计不到人**：可能该公司部分作品 staff 数据为空，或当前筛选过严；可先点上方「清空」恢复全部作品再统计。
- **统计结果缺失个别作品**：Bangumi 部分条目 staff 数据不全，属正常现象；统计页会提示失败数量。
- **刷新后结果消失**：这是预期行为；缓存只用于当次打开期间切页，需长期留存时请先导出。
- **找不到制片样本**：检查载入的是人物 ID，且该人物有明确动画/制作制片署名的作品；普通制片称谓会单独列出，其他岗位不代替此身份。
- **没有核心候选**：查看作品数、跨项目跨度、外部履历核查范围和每人的依据；没有通过门槛不等于已证明其不是核心。
- **页面渲染异常**：按 F12 打开控制台，把报错信息发给我排查。
