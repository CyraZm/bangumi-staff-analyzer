# bangumi-staff-analyzer

Bangumi 制作人员（staff）分析与收集工具。纯前端 Web 应用，无需安装、无需 Token、无需后端。

## 功能

- **公司 staff 频率统计**：搜索一家制作公司（如「京都动画」），统计其作品中哪些制作人员出现次数最多、各自担任过哪些职务；作品可按参与身份（如动画制作）筛选，结果可按职务（监督/原画/演出等）筛选，**每个职务单独计数**（如某人导演×10、演出×20，筛选某职务时显示对应次数）。
- **个人共事统计**：搜索一位个人（如某位制片人/监督），统计与 TA 共事过的人及共事作品数——可用于梳理「某制片人的班底/人脉」。
- **作品对比（支持多部）**：默认选两部作品对比，可继续添加更多作品（最多 8 部）。查看同时出现在两部（或全部）作品中的 staff，以及他们在每部作品里各自担任的职务；也列出只出现在某部作品的独有 staff（同一人在一部作品里的多个职务会合并显示，不重复计数）。
- **公司对比**：选两家及以上制作公司，自动聚合各公司「动画制作」作品的全部 staff，找出同时出现在多家公司作品中的 staff（带出现次数与职务）——可用来观察 staff 在不同公司间的流动。
- **我的分类收集**：给感兴趣的 staff 打标签、写备注、建自定义分组（如「山田尚子班底」），数据保存在本地浏览器（IndexedDB），支持导出 JSON / CSV 备份。

## 数据来源与隐私

- 数据来自 Bangumi 官方公开 API（https://api.bgm.tv），无需登录、无需 Access Token。
- 搜索时的「个人/公司」标签来自 Bangumi 人物条目的类型字段；「制片人/画师/声优」等来自其职业（career）字段的官方分类，由 Bangumi 用户维护，非本工具自行判断。
- 所有抓取到的数据与你的标记/分组都只保存在**本地浏览器**中，不上传任何服务器。
- 清除浏览器站点数据会清空本工具的全部本地数据，建议定期导出备份。

## 如何打开 / 关闭（重要）

推荐用 **`start.command`** 这个文件，双击即可用，不用记任何命令：

1. **打开**：双击项目里的 `start.command` → 会自动启动服务并打开浏览器（地址 `http://localhost:8000`）。
2. **关闭**：把弹出的黑色窗口（终端）关掉，或在该窗口里按 `Ctrl + C`。
3. 若提示「端口已被占用」，说明服务已经在运行，脚本会直接帮你打开浏览器。

> 另一种方式：直接双击 `index.html` 也能用（不需要服务）。
> ⚠️ 注意：这两种方式（localhost 和 index.html）的数据**不互通**，请固定用同一种方式打开，避免数据"消失"。

手动方式（进阶，可选）：

```bash
cd bangumi-staff-analyzer
python3 -m http.server 8000
# 浏览器访问 http://localhost:8000，关闭用 Ctrl+C
```

## 关于请求频率

批量统计（如公司几百部作品）会向 Bangumi API 逐个请求，请合理设置：

- **并发数**：建议 3-10，默认 5（设置里可调，1-20）。
- **请求间隔**：建议 150-500ms，默认 200ms。
- 遇到大量 `429` 报错或「请求多次失败」时，请把并发降到 3、间隔加到 400ms 以上再重试。
- 已抓取的数据会缓存在本地，重复统计同一批作品会直接命中缓存，不会重复请求。

## 常见问题

- **搜索无结果**：换关键词再试。
- **公司统计不到人**：可能该公司部分作品 staff 数据为空，或当前筛选过严；可先点上方「清空」恢复全部作品再统计。
- **统计结果缺失个别作品**：Bangumi 部分条目 staff 数据不全，属正常现象；统计页会提示失败数量。
- **某个 staff 点击「收集」没反应**：确认浏览器支持 IndexedDB，且未以隐私模式阻止本地存储。
- **页面渲染异常**：按 F12 打开控制台，把报错信息发给我排查。
